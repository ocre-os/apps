# OCRE OS Status v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a live, public, read-only OCRE OS Status application in Apps that diagnoses Core and Staging without depending on the ThinkPad for its own UI.

**Architecture:** Add a sanitized status contract to OCRE-OS, validate it on Staging first, then build a static browser monitor in `ocre-os/apps` that combines external reachability with that contract. Normal and Matrix renderers consume one client-side state model; no persistence or monitoring backend is introduced.

**Tech Stack:** Existing OCRE-OS API/test stack; static HTML/CSS/JavaScript in OCRE Apps; Canvas/CSS for Matrix Mode; GitHub Actions FTPS deployment.

**Spec:** `docs/superpowers/specs/2026-10-03-os-status-v1-design.md`

## Global Constraints

- No database or business-rule changes.
- No persistence, cron, incident history, accounts, or private data in Status v1.
- Automatic refresh is exactly 10 seconds while the page is open; manual refresh is immediate.
- Every request is finite and superseded cycles cannot overwrite fresher state.
- Core and Staging are isolated targets.
- Public diagnostic output is sanitized and read-only.
- Critical: external access, Web, API, PostgreSQL, schema/migration compatibility.
- Degradable: notification worker, storage/files, email/notification capability where observable, PWA support endpoints.
- Missing/unobservable internal checks are UNKNOWN, never fabricated.
- Core/production deployment requires explicit user approval; Staging and reversible Apps publication may be validated first.
- Matrix Mode uses original generated resources and never fabricates operational-looking telemetry.

## Review Focus

- Whole origin unavailable: external state fails while internal components become UNKNOWN rather than falsely failed.
- Slow/hung request: finite timeout completes the cycle and the UI remains interactive.
- Rapid Core/Staging switching: late response from the prior environment never contaminates the selected environment.
- Malformed/partial status payload: valid external observations survive and missing contract fields become UNKNOWN.
- Reduced-motion/mobile: Status remains readable and Matrix Mode remains escapable without relying on high-motion effects.
